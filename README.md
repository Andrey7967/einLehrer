# Практика — тренажёр 1С

Статическое приложение на React + TypeScript. Внутри 961 вопрос из 14 глав исходного PDF, 78 изображений и отметки правильных ответов по зелёному цвету букв. Приложение не отправляет ответы или прогресс на сервер.

## Быстрый запуск готового приложения

На Windows запустите **start.cmd**. Нужен установленный Node.js 22.18+ (рекомендуется Node.js 24). Готовая сборка находится в `dist`; устанавливать зависимости для её запуска не нужно.

Либо из папки проекта:

```powershell
node scripts/serve.mjs
```

Откройте http://localhost:4173. Окно сервера оставьте открытым. Это только раздача статических файлов, без API и базы данных. Двойной щелчок по `dist/index.html` не подходит: браузер ограничивает загрузку JSON и service worker через file://.

## Режимы

- **Изучение:** список вопросов, все варианты и отмеченный правильный ответ. Поиск и фильтр по главе.
- **Марафон:** полный банк по порядку. Переключатель «Перемешать» на главной задаёт случайный порядок нового марафона без повторов.
- **Общий тест:** 14 вопросов, по одному случайному из каждой главы.
- **Разделы:** изучение или тест по всем вопросам одной главы.
- Верный выбор показывает галочку и автоматически переводит дальше через 1,1 секунды. Ошибка показывает правильный ответ с ключевыми словами; переход кнопкой «Далее».
- Прогресс, текущая сессия, случайный порядок, правки подсказок и отметки сверки сохраняются на устройстве. Экспорт/импорт прогресса доступен внизу боковой панели.

## Ключевые слова

Исходные строки не редактируются. `public/data/keywords.json` содержит отдельные диапазоны UTF-16, точный текст фрагмента и SHA-256 текста. Несовместимые диапазоны не отображаются.

Над экранами находится переключатель источника подсказок:

- **Алгоритм:** автоматический подбор по различиям слов. Доступен для всего банка, файл `public/data/keywords.json`.
- **Смысловой разбор:** отдельный авторский набор после прочтения условий и всех вариантов ответа. По договорённости полностью подготовлен первый раздел — **77 вопросов**, **154 разметки** (вопрос + правильный ответ) и **77 смысловых пояснений**. Файл `public/data/keywords-semantic.json`.

В смысловом наборе выделяются признаки, меняющие ответ: обычные/управляемые формы, новый/существующий элемент, отрицания, ограничения и направления связей. Пояснения помогают расшифровать ответы «Варианты 1 и 2» и различить похожие формулировки. В изучении они видны сразу, в марафоне и тестах — только после ответа, в разборе ошибок — после завершения.

В остальных 884 вопросах смыслового набора пока нет. При его выборе они показываются без подсветки и с явной отметкой об отсутствии разбора. Автоматические подсказки туда не подставляются.

Исходный авторский выбор фраз и пояснений хранится в `scripts/semantic-chapter-1.ts`. `scripts/build-semantic.ts` только находит выбранные фразы в неизменяемом тексте и проверяет диапазоны; он не выбирает ключевые слова по частотности или шаблонам. При расположении фразы на нескольких исходных строках выделяются её подлинные символы, включая исходные переносы.

Кнопка «Ключевые слова» открывает редактор текущего набора: выделите фразу мышью либо введите её точно, затем добавьте выделение. Для повторяющейся фразы выбирается первое совпадение. Правки двух источников сохраняются отдельно и входят в экспорт прогресса. Выбор источника сохраняется после перезагрузки; сессия и результат при переключении не сбрасываются. Старые правки остаются в алгоритмическом наборе.

Номера и порядок вариантов неизменны: в источнике есть ответы «Варианты 1 и 2». Перемешиваются только вопросы.

## Надёжность переноса

- `scripts/parse_pdf.py` извлекает текстовые строки, координаты, цвета символов и изображения. Главы обрабатываются в порядке появления на странице; переносы вопросов и ответов между страницами сохраняются.
- Не исправляются формулировки, символы кода, опечатки и дефисы. Переносы строк хранятся в тексте; визуально браузер переносит текст под ширину экрана.
- В PDF обнаружены неверные Unicode-отображения лигатур `ft`, `ti`, `tt`: они извлекались как нулевой символ в словах Microsoft, Shift, ActiveX и других. `scripts/font_recovery.py` восстанавливает компоненты непосредственно из таблицы GSUB встроенного TrueType-шрифта и соответствия CID→GID. Это восстановление глифа, без подбора слов или исправления содержания. Основания сохранены в `fontRecoveries` отчёта; исходный PDF не изменяется.
- На всех страницах сравниваются наборы символов двух независимых библиотек: pdfplumber и pypdf. Единственное различие — лигатура `ﬂ` и последовательность `fl` на странице 2. Оно признано эквивалентным только при сравнении; текст банка не изменён. Страница также осмотрена визуально.
- `scripts/audit_pdf.py` повторно проверяет каждый текстовый блок по строке и координатам PDF, полноту покрытия исходных строк, отсутствие дублирования, цвет каждого ответа и координаты каждой картинки.
- В `public/data/import-report.json` находится журнал переноса; в `audit-report.json` — итог повторной проверки.
- В интерфейсе «Сверка с PDF» рядом показаны оригинальные страницы и перенесённый вопрос. Можно сохранить отметку и замечание.

**Полная ручная визуальная сверка всех 961 вопросов не выполнена.** Автоматические проверки не заменяют её, и приложение не выдаёт их за ручную проверку. Смысловая правильность ответов самого исходного PDF также не пересматривается.

## PWA и офлайн

В production-сборке service worker сохраняет оболочку приложения. Нажмите «Скачать для офлайн» и дождитесь «Готово к работе без интернета»: загрузятся весь банк, картинки, исходный PDF и страницы для сверки. Прерванную загрузку можно повторить — уже скачанные файлы используются повторно. Готовность ставится только после полной загрузки.

Установка доступна через меню браузера или кнопку приложения, когда браузер поддерживает событие установки. На iPhone используйте Safari → «Поделиться» → «На экран Домой». Для PWA нужен HTTPS или localhost. При публикации на обычном HTTP установку и офлайн-режим браузер может ограничить.

Настоящая браузерная проверка мобильной вёрстки, установки и service worker в этой среде заблокирована. Логика интерфейса проверена в DOM-среде, а service worker — отдельным тестом Cache API, включая прерывание, повтор загрузки и офлайн-выдачу данных. Для окончательной приёмки проверьте установленное приложение в целевом браузере.

## Разработка и проверки

### Публикация на GitHub Pages

В проект включён `.github/workflows/deploy-pages.yml`. Он проверяет банк и логику, собирает полный `dist` с изображениями и публикует его после push в `main`.

1. Создайте пустой публичный репозиторий на GitHub, например `1c-trainer`. Не добавляйте автоматически README, .gitignore и лицензию при создании, чтобы не получить независимый начальный коммит.
2. В PowerShell в папке проекта выполните команды, заменив `YOUR_LOGIN` на свой логин:

```powershell
git init -b main
git add .
git commit -m "Add 1C trainer"
git remote add origin https://github.com/YOUR_LOGIN/1c-trainer.git
git push -u origin main
```

3. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Во вкладке **Actions** откройте **Publish trainer to GitHub Pages**. Если первая попытка прошла до включения Pages и завершилась ошибкой настройки, нажмите **Re-run all jobs**; либо запустите workflow вручную через **Run workflow** для ветки `main`.
5. После успешной публикации откройте адрес из deployment: обычно `https://YOUR_LOGIN.github.io/1c-trainer/`.

`base: './'` уже настроен, поэтому имя репозитория не нужно прописывать в конфигурации приложения. После публикации обновления отправляются обычными `git add`, `git commit`, `git push`.

В Git отправляются исходники, `.github` и `public/data`. `node_modules`, `dist`, временные файлы и ZIP исключены через `.gitignore`; GitHub сам соберёт полное содержимое сайта. ZIP нельзя просто загрузить в репозиторий как сайт.

Публичная публикация делает доступными сайт, банк вопросов и включённый PDF. Прогресс каждого пользователя остаётся в его браузере; перенести его можно экспортом и импортом. На HTTPS-адресе Pages доступны необходимые условия для PWA, а установить приложение можно после открытия сайта в поддерживающем браузере.

Официальная инструкция: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages

### Локальная разработка

```powershell
npm install
npm run dev
npm test
npm run validate
npm run test:ui
npm run build
npm run test:pwa
```

`npm run build` создаёт полный `dist` и версионированный service worker. Всё содержимое полной сборки `dist` можно разместить на статическом HTTPS-хостинге, в том числе в подкаталоге. API, серверная обработка и внешние CDN не нужны. В архиве большие файлы данных хранятся один раз, в `public/data`; встроенный статический сервер автоматически отдаёт их оттуда. Перед публикацией на другом хостинге выполните сборку либо скопируйте `public/data` в `dist/data`.

Для повторного импорта нужен Python 3.12+:

```powershell
python -m pip install -r requirements.txt
python scripts/parse_pdf.py
python scripts/audit_pdf.py
node --experimental-strip-types scripts/keywords.ts
node --experimental-strip-types scripts/build-semantic.ts
npm run validate
npm run build
```

Повторная генерация каждого набора перезаписывает только соответствующий поставляемый файл разметки. Пользовательские локальные правки хранятся отдельно. Банк привязан к SHA-256 исходного файла; сессия от другой версии не восстанавливается.

## Структура

```text
src/                  Интерфейс, модели, проверка ответов и разметки
scripts/              Парсер, аудит, генерация подсказок, сборка PWA
tests/                Тесты логики и service worker
public/data/          Банк, подсказки, изображения и исходные страницы
dist/                 Готовое статическое приложение
start.cmd             Запуск на Windows без установки npm-зависимостей
```
